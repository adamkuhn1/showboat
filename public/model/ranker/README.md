# Production candidate-ranker artifact

This directory holds the **shipped** trained model. It is served at
`/model/ranker/` (Vite copies `public/` verbatim into `dist/`), fetched by
`src/ai/neural/evaluator.ts`, and run in the browser with `onnxruntime-web`.

**Currently staged: the Phase 2E Deep Sets (relational) ranker**, adopted in
place of the original Phase 2D MLP after Team B's independent research
recommended it — see
`docs/repair/product-proof-sprint/showboat-model-research/REPORT.md` for the
full comparison and `docs/repair/showboat-ml/phase-2d/` for the superseded
MLP's own history (kept, not deleted — it's the baseline the Phase 2E report
compares against).

| File | What it is |
|---|---|
| `showboat-ranker-phase2e-deepsets.onnx` | The Phase 2E candidate-conditioned Deep Sets ranker (entity/relational architecture over the 16 balls), opset 17, 176,831 bytes. Input `candidate_features` `[N, 68]` float32 — **identical contract to the Phase 2D MLP it replaces**, entity construction happens inside the graph; output `logit` `[N, 1]` float32. |
| `manifest.json` | Generated, never hand-edited, by `scripts/stage-production-model-phase2e.mjs`. Integrity (sha256 + byte length), the feature-schema contract, Platt calibration parameters, full provenance back to the training checkpoint, the artifact's own known limitations (evaluated from this specific shipped seed's numbers, not a 5-seed ensemble average), and the per-kind confidence weights the runtime applies. |

## Why this is committed

`training/ranker/.gitignore` says Phase 2C+ artifacts are "reproducible on
demand, not committed." That is the right policy for *experiment* weights. It
is not a delivery mechanism for a feature that ships: a fresh clone with no
Python environment must be able to run `npm ci && npm run build` and get a
working neural-enabled bundle.

The alternatives were considered and rejected on the evidence:

- **External artifact URL + SHA check** — only justified if the file is too
  large for git. It is 173 KB. There is no upside, and a URL is one more thing
  that can rot or become a network dependency of the build.
- **Build-time training** — training this model is tens of seconds of PyTorch
  per seed on a 120k-row dataset that is itself gitignored and took a
  multi-day supervised generation run to produce. Not CI-suitable, not
  reproducible from a clone with no Python environment.

So: commit the artifact, and make its integrity checkable at four
independent points rather than trusted.

## Integrity chain

1. `scripts/stage-production-model-phase2e.mjs` refuses to stage an artifact
   whose sha256 doesn't match
   `training/ranker/phase2e/results/artifact/MANIFEST_deepsets.json` (the
   reviewed Phase 2E export manifest, committed).
2. `src/ai/neural/productionModel.test.ts` re-checks, on every `npm test`, that
   the committed bytes hash to the manifest value, that both manifests agree,
   and that the schema version and input width match `src/ai/ranker/schema.json`
   — the same file `encode.ts` and `schema.py` read.
3. `scripts/verify-build-model.mjs` runs as part of `npm run build` and fails
   the build if `dist/model/ranker/` is missing, truncated, or hash-mismatched
   — it reads the artifact filename from the manifest itself, so it is not
   tied to any one phase's naming.
4. At runtime, `tryLoadRankerModel` re-hashes the fetched bytes with WebCrypto,
   checks the byte length, and runs a real zero-filled probe inference before
   the model is allowed to influence a shot. Any failure sets status `invalid`
   (distinct from `absent`), logs a `console.error`, and the app plays
   classical with an explicit "classical fallback" line in the overlay.

## Regenerating

Only needed when adopting a new reviewed artifact.

```
# 1. produce the ONNX + training manifest (needs the Python env + checkpoints)
cd apps/showboat/training/ranker/phase2e
python export_onnx.py --variant deepsets

# 2. stage it here (verifies provenance, derives manifest.json mechanically)
cd apps/showboat
node scripts/stage-production-model-phase2e.mjs
npm test && npm run build
```

To revert to the Phase 2D MLP (e.g. if a regression is found), run
`node scripts/stage-production-model.mjs` instead — both scripts write the
same `manifest.json`/artifact-pair shape, so the rest of the runtime needs no
changes either way; only `productionModel.test.ts`'s `TRAINING_MANIFEST`
constant and `hybrid.test.ts`'s `modelId` assertion would need to point back
at Phase 2D's manifest.

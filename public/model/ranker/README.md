# Production candidate-ranker artifact

This directory holds the **shipped** trained model. It is served at
`/model/ranker/` (Vite copies `public/` verbatim into `dist/`), fetched by
`src/ai/neural/evaluator.ts`, and run in the browser with `onnxruntime-web`.

| File | What it is |
|---|---|
| `showboat-ranker-phase2d.onnx` | The Phase 2D candidate-conditioned MLP, opset 17, 14,185 bytes. Input `candidate_features` `[N, 68]` float32; output `logit` `[N, 1]` float32. |
| `manifest.json` | Generated, never hand-edited. Integrity (sha256 + byte length), the feature-schema contract, Platt calibration parameters, full provenance back to the training checkpoint, the artifact's own known limitations, and the per-kind confidence weights the runtime applies. |

## Why this is committed

`training/ranker/.gitignore` says Phase 2C+ artifacts are "reproducible on
demand, not committed." That is the right policy for *experiment* weights. It
is not a delivery mechanism for a feature that ships: a fresh clone with no
Python environment must be able to run `npm ci && npm run build` and get a
working neural-enabled bundle.

The alternatives were considered and rejected on the evidence:

- **External artifact URL + SHA check** — only justified if the file is too
  large for git. It is 14 KB. There is no upside, and a URL is one more thing
  that can rot or become a network dependency of the build.
- **Build-time training** — training this model is minutes of PyTorch on a
  120k-row dataset that is itself gitignored and took a multi-day supervised
  generation run to produce. Not CI-suitable, not fast, not reproducible from
  a clone.

So: commit the 14 KB artifact, and make its integrity checkable at three
independent points rather than trusted.

## Integrity chain

1. `scripts/stage-production-model.mjs` refuses to stage an artifact whose
   sha256 doesn't match `training/ranker/phase2d/results/artifact/MANIFEST.json`
   (the reviewed Phase 2D export manifest, committed).
2. `src/ai/neural/productionModel.test.ts` re-checks, on every `npm test`, that
   the committed bytes hash to the manifest value, that both manifests agree,
   and that the schema version and input width match `src/ai/ranker/schema.json`
   — the same file `encode.ts` and `schema.py` read.
3. `scripts/verify-build-model.mjs` runs as part of `npm run build` and fails
   the build if `dist/model/ranker/` is missing, truncated, or hash-mismatched.
4. At runtime, `tryLoadRankerModel` re-hashes the fetched bytes with WebCrypto,
   checks the byte length, and runs a real zero-filled probe inference before
   the model is allowed to influence a shot. Any failure sets status `invalid`
   (distinct from `absent`), logs a `console.error`, and the app plays
   classical with an explicit "classical fallback" line in the overlay.

## Regenerating

Only needed when adopting a new reviewed artifact.

```
# 1. produce the ONNX + training manifest (needs the Python env + checkpoints)
cd apps/showboat/training/ranker/phase2d
python export_onnx.py --results results --out results/artifact

# 2. stage it here (verifies provenance, derives manifest.json mechanically)
cd apps/showboat
npm run model:stage
npm test && npm run build
```
